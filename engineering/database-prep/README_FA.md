# بسته آماده‌سازی دیتابیس Ai_Tourism پیش از Codex

نسخه: `0.2`  
وضعیت: بسته آماده اجرا و آزمون روی سیستم توسعه‌دهنده؛ هنوز روی Docker Desktop کاربر اجرا نشده است.

## هدف

این بسته فقط زیرساخت دیتابیس MVP و کنترل کیفیت داده را آماده می‌کند. هدف آن انتخاب مدل Embedding یا پیاده‌سازی الگوریتم RAG نیست.

- PostgreSQL 17 مستقل از سرویس PostgreSQL ویندوز و کانتینرهای پروژه‌های دیگر
- نسخه‌های هدف Image: PostgreSQL 17، PostGIS 3.6.x (در حال حاضر 3.6.4) و pgvector 0.8.7؛ تست نسخه Extensionها را کنترل می‌کند.
- PostGIS برای ذخیره مختصات و آزمون فاصله مکانی
- pgvector برای ذخیره و بازیابی بردارها
- حفظ ۱۵ رکورد فعلی پروژه به‌عنوان داده ورودیِ تأییدنشده
- افزودن ۱۲ مقصد کاملاً مصنوعی، ۱۲ سند و ۲۴ Chunk برای تست؛ به‌علاوه ۱۰ مقصد میراث جهانی با منبع رسمی، ۱۰ سند و ۲۰ Chunk واقعیِ خلاصه‌سازی‌شده
- افزودن یک گراف انتهابه‌انتهای مصنوعی برای تست روابط کاربر، مکالمه، سفر، پیشنهاد و برنامه سفر
- تست تعداد دقیق جدول‌ها و رکوردها، Seed تکرارپذیر، قیود و روابط، PostGIS، قرارداد ذخیره/بازیابی بردار و Viewهای جلوگیری از انتشار داده تأییدنشده

> **نکته نسخه Image (نوامبر ۲۰۲۶):** تگ `postgis/postgis:17-3.6` بر پایه Debian Trixie و PostGIS 3.6.x است. تگ‌های Debian مبتنی بر PostGIS 3.5 دیگر به‌روزرسانی نمی‌شوند و جابه‌جایی یک Volume موجود از خانواده 3.5 به 3.6 تغییر سیستم‌عامل پایه نیز دارد؛ این بسته فقط یک Volume کاملاً جدید و مستقل می‌سازد و برای ارتقای هیچ دیتابیس موجودی طراحی نشده است. به Volumeهای سایر پروژه‌ها این Image را متصل نکن.

## محل استخراج

ZIP را در ریشه مخزن محلی استخراج کن؛ ساختار نهایی باید این‌گونه باشد:

```text
C:\Projects\Ai_Tourism\
├── database\
│   └── tourism_points.sql       # فایل فعلی پروژه؛ بدون تغییر
└── engineering\
    └── database-prep\
        ├── compose.yaml
        ├── Dockerfile
        ├── scripts\
        ├── sql\
        └── ...
```

این بسته فایل `database/tourism_points.sql` موجود را فقط می‌خواند و یک کپی از آن را داخل پوشه `legacy` خودش قرار می‌دهد. فایل اصلی مخزن را تغییر نمی‌دهد.

## اجرا

PowerShell را از ریشه مخزن باز کن:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\engineering\database-prep\scripts\Initialize-Database.ps1
```

اسکریپت:

1. Docker Engine را بررسی می‌کند.
2. یک `.env` محلی با رمز تصادفی می‌سازد؛ رمز را چاپ نمی‌کند.
3. Image اختصاصی PostgreSQL را می‌سازد.
4. کانتینر `ai-tourism-postgres` را روی `127.0.0.1:55433` بالا می‌آورد.
5. فایل فعلی `database/tourism_points.sql` را در دیتابیس تازه وارد می‌کند.
6. Migrationها و داده‌های آزمایشی را با Checksum ثبت و اجرا می‌کند.
7. اگر جدول موجودی بدون سابقه Migration پیدا کند، متوقف می‌شود و دیتابیس را Reset نمی‌کند.

سپس تست‌ها:

```powershell
.\engineering\database-prep\scripts\Test-Database.ps1
```

پیش از اتصال به دیتابیس، یک Validator آفلاین با Python استاندارد تعداد و Hash مربوط به ۱۲ سند/۲۴ Chunk مصنوعی و ۱۰ سند/۲۰ Chunk دارای منبع خارجی را کنترل می‌کند. سپس Runner هشت گروه تست SQL دیتابیس را اجرا می‌کند: نسخه Extensionها، تعداد/شمارش دقیق جدول و رکورد، تکرارپذیری Seed، PostGIS و Indexهای GiST/GIN، تطبیق Hash واقعی متن ذخیره‌شده، ذخیره و بازیابی دقیق بردار با ابعاد متفاوت و رد ابعاد ناسازگار، یکپارچگی روابط/امتیازها/برنامه سفر، آزمون مثبت و منفی Viewهای انتشار Production، و سطح دسترسی نقش اپلیکیشن. نقش اپلیکیشن فقط Viewهای داده تأییدشده را می‌خواند و به جداول خام دانش/منابع/بردارها دسترسی مستقیم ندارد.

برای متوقف کردن کانتینر، بدون حذف Volume:

```powershell
.\engineering\database-prep\scripts\Stop-Database.ps1
```

## تنظیم اتصال

```text
Host: localhost
Port: 55433
Database: ai_tourism_dev
Application username: ai_tourism_app
Application password: مقدار POSTGRES_APP_PASSWORD در فایل محلی engineering/database-prep/.env
```

نقش `ai_tourism_owner` فقط برای Migration و مدیریت است؛ اپلیکیشن نباید با نقش مالک/ادمین متصل شود. نقش اپلیکیشن روی Schema دانش/RAG فقط خواندنی است و اجازه تغییر مقصد، منشأ، اسناد یا بردارها را ندارد.

Binding پورت فقط روی Loopback است؛ دیتابیس از شبکه عمومی در دسترس نیست.

## سیاست ایمنی داده

- ۱۵ مقصد فعلی پروژه همچنان `needs_review` و `pending` هستند. مختصات آن‌ها خالی و `coordinate_role=unknown` باقی می‌ماند.
- ۱۰ رکورد UNESCO منبع و مختصات رسمی دارند و `verification_status=verified` هستند، اما عمداً `status=needs_review` دارند؛ بنابراین تا بازبینی و تأیید محصول در Viewهای Production و RAG منتشر نمی‌شوند. مختصات آن‌ها `property_reference` است، نه ورودی بازدیدکننده.
- ۱۲ مقصد QA دارای `coordinate_role=test_fixture` هستند.
- ۱۲ مقصد QA دارای `record_origin='synthetic_fixture'`، `is_synthetic=true` و `status='test_only'` هستند. مختصات آن‌ها ساختگی و صرفاً برای آزمون PostGIS هستند.
- اسناد و Chunkهای QA نیز با `test_only` و `is_synthetic=true` مشخص‌اند.
- کاربر، مکالمه، سفر، پیشنهاد، امتیازها، برنامه سفر و بازخورد نمونه همگی `is_synthetic=true` هستند.
- لینک‌های نمونه از دامنه رزروشده `.invalid` استفاده می‌کنند و غیرفعال‌اند.
- هیچ Embedding واقعی یا تماس Remote LLM تولید نمی‌شود.
- Viewهای مخصوص Production فقط داده‌های فعال و تأییدشده با منشأ معتبر را نمایش می‌دهند؛ مسیر اسناد، Chunkها و Embeddingها نیز به همان Viewهای کنترل‌شده محدود است. در دیتابیس تازه همه این Viewها عمداً خالی هستند؛ داده‌های UNESCO نیز تا تأیید محصول منتشر نمی‌شوند.

**مهم:** این نسخه علاوه بر ۱۵ رکورد قدیمیِ تأییدنشده و ۱۲ مقصد مصنوعی QA، یک بسته اولیه شامل ۱۰ اثر میراث جهانی ایران با ارجاع رسمی به یونسکو، مختصات مرجع، ۱۰ سند فارسی و ۲۰ Chunk غیرمصنوعی دارد. این ۱۰ رکورد از نظر منشأ منبع بررسی شده‌اند، اما همگی `needs_review` باقی می‌مانند و تا تأیید صریح محصول وارد Viewهای Production/RAG نمی‌شوند. این مجموعه، پوشش کامل مقاصد ایران یا آمادگی پایلوت نیست؛ پس از عبور از تست‌های دیتابیس، می‌توانیم Batchهای واقعی بیشتری را با همین کنترل‌های منبع/مکان/مجوز/بازبینی اضافه کنیم. این دیتابیس صرفاً Development و Test است و هیچ داده مصنوعی نباید به Production منتقل شود.

## ایمنی محیط

- نام کانتینر: `ai-tourism-postgres`
- نام Volume: `ai_tourism_pgdata`
- پورت: `127.0.0.1:55433`
- کانتینرها و Volumeهای `ai-cosulation-worker-pg16-test` و `cheshm_bidar-app-1` هدف این بسته نیستند.
- سرویس بومی PostgreSQL 17 ویندوز متوقف، بازپیکربندی یا حذف نمی‌شود.
- اسکریپت توقف فقط `docker compose stop db` را اجرا می‌کند؛ هیچ‌جا `down -v` اجرا نمی‌شود.

## نتیجه و محدودیت فعلی

Validator آفلاین Python برای ۱۲ سند/۲۴ Chunk مصنوعی و ۱۰ سند/۲۰ Chunk واقعی اجرا و کنترل Hash و تعداد را بررسی می‌کند. تست‌های PostgreSQL شامل شمارش دقیق، تکرارپذیری Seed، PostGIS، ذخیره/بازیابی بردار، Hash سمت دیتابیس، روابط، Viewهای انتشار و مجوزهاست. این تست‌های دیتابیس هنوز باید روی Docker Desktop ویندوز اجرا شوند. تست pgvector یک تست قرارداد ذخیره و nearest-neighbor مصنوعی است و کیفیت معنایی یا Recall واقعی RAG را اثبات نمی‌کند.

در محیط اجرای ChatGPT به Docker Engine سیستم Windows تو دسترسی مستقیم ندارم؛ بنابراین هنوز ادعا نمی‌کنم که Migrationها روی سیستم تو اجرا شده‌اند. این بسته شامل تست‌های اجرایی است که پس از اجرا باید سبز شوند. اگر خطایی رخ دهد، خروجی کامل همان تست را بررسی و اصلاح می‌کنیم؛ بعد از عبور آن‌ها به Codex می‌رسیم.
