# بسته آماده‌سازی دیتابیس Ai_Tourism پیش از Codex

نسخه: `0.5`
وضعیت: **دیتابیس مشترک مالک در 2026-11-05 همچنان در Migration 0006 / ۳۰ جدول / ۴۱۹ ردیف است. Migration 0007 روی آن اعمال نشده است.** Migration 0007 یک وضعیت اختیاری دیگر با ۶۹۵ ردیف تعریف می‌کند و به تأیید جداگانهٔ مالک نیاز دارد.

## هدف

این بسته فقط زیرساخت دیتابیس MVP و کنترل کیفیت داده را آماده می‌کند. هدف آن انتخاب مدل Embedding یا پیاده‌سازی الگوریتم RAG نیست.

- PostgreSQL 17 مستقل از سرویس PostgreSQL ویندوز و کانتینرهای پروژه‌های دیگر
- نسخه‌های هدف Image: PostgreSQL 17، PostGIS 3.6.x (در حال حاضر 3.6.4) و pgvector 0.8.7؛ تست نسخه Extensionها را کنترل می‌کند.
- PostGIS برای ذخیره مختصات و آزمون فاصله مکانی
- pgvector برای ذخیره و بازیابی بردارها
- حفظ ۱۵ رکورد فعلی پروژه به‌عنوان داده ورودیِ تأییدنشده
- افزودن ۱۲ مقصد کاملاً مصنوعی، ۱۲ سند و ۲۴ Chunk برای تست؛ به‌علاوه ۱۷ مقصد میراث جهانی با منبع رسمی، ۱۷ سند فارسی و ۳۴ Chunk در دو Batch
- افزودن یک گراف انتهابه‌انتهای مصنوعی برای تست روابط کاربر، مکالمه، سفر، پیشنهاد و برنامه سفر
- تست تعداد دقیق جدول‌ها و رکوردها، Seed تکرارپذیر، قیود و روابط، PostGIS، قرارداد ذخیره/بازیابی بردار و Viewهای جلوگیری از انتشار داده تأییدنشده

> **نکته نسخه Image (نوامبر ۲۰۲۶):** تگ `postgis/postgis:17-3.6` بر پایه Debian Trixie و PostGIS 3.6.x است. تگ‌های Debian مبتنی بر PostGIS 3.5 دیگر به‌روزرسانی نمی‌شوند و جابه‌جایی یک Volume موجود از خانواده 3.5 به 3.6 تغییر سیستم‌عامل پایه نیز دارد؛ این بسته فقط یک Volume کاملاً جدید و مستقل می‌سازد و برای ارتقای هیچ دیتابیس موجودی طراحی نشده است. به Volumeهای سایر پروژه‌ها این Image را متصل نکن.

## اجرا

> Migration `0008_authentication_foundation` افزایشی و opt-in است. برای دیتابیس موجود، فقط پس از تأیید صریح مالک و روی محیط مجاز از `-ApplyAuthenticationMigrationToExistingDatabase` استفاده کنید. Validator حالت‌های دقیق 0006/419، 0007/695، 0006+0008/420 و 0007+0008/696 را تشخیص می‌دهد. Migration هیچ شمارهٔ قدیمی را تأیید نمی‌کند. این مستند مجوز اجرای آن روی دیتابیس مشترک نیست.

PowerShell را از ریشه مخزن باز کن. برای یک دیتابیس کاملاً تازه، مسیر Initialize همان ترتیب bootstrap و migrationهای مستندشده را طی می‌کند. برای دیتابیس موجود 0006، Initialize ابتدا ledger، checksumها و Manifest کامل را فقط می‌خواند و در حالت پیش‌فرض پیش از هر Migration متوقف می‌شود. اجرای 0007 روی دیتابیس موجود فقط پس از تأیید جداگانهٔ مالک و opt-in صریح مجاز است. دیتابیس 0007 از قبل معتبر، فقط بررسی و بدون تغییر باقی می‌ماند.

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\engineering\database-prep\scripts\Initialize-Database.ps1
```

فقط پس از تأیید جداگانهٔ مالک برای ارتقای دیتابیس موجود 0006، از opt-in زیر استفاده کن؛ این سوییچ Migration 0007 را اجرا می‌کند:

```powershell
.\engineering\database-prep\scripts\Initialize-Database.ps1 -ApplyPendingMigrationsToExistingDatabase
```

اسکریپت:

1. Docker Engine را بررسی می‌کند.
2. یک `.env` محلی با رمز تصادفی می‌سازد؛ رمز را چاپ نمی‌کند.
3. Image اختصاصی PostgreSQL را می‌سازد.
4. کانتینر `ai-tourism-postgres` را روی `127.0.0.1:55433` بالا می‌آورد.
5. فایل فعلی `database/tourism_points.sql` را در دیتابیس تازه وارد می‌کند.
6. Migrationها و داده‌های آزمایشی را با Checksum ثبت و اجرا می‌کند.
7. دیتابیس موجود را با ledger دقیق و تعداد ردیف‌ها تشخیص می‌دهد؛ فقط وضعیت کاملاً تازه یا 0006 / 419 یا 0007 / 695 را می‌پذیرد.
8. برای دیتابیس موجود 0006 بدون سوییچ صریح متوقف می‌شود؛ ledger، checksum، تعداد نامتوقع یا حالت ناقص باعث توقف fail-closed می‌شوند.
9. برای دیتابیس موجود 0007 معتبر، هیچ migration یا seedای را دوباره اجرا نمی‌کند.

سپس تست‌ها:

```powershell
.\engineering\database-prep\scripts\Test-Database.ps1
```

پیش از اتصال به دیتابیس، Validator آفلاین Python تعداد و Hash محتوا را کنترل می‌کند. Runner از Migration ledger و Checksumها وضعیت را تشخیص می‌دهد، سپس تمام ۳۰ شمارش جدول را با Manifest همان وضعیت تطبیق می‌دهد. برای 0006، ۴۱۹ ردیف و تست‌های 000–008 لازم‌اند؛ Migration 0007 و تست 009 اجرا نمی‌شوند. برای 0007، ۶۹۵ ردیف و تست‌های 000–009 لازم‌اند. Validator هیچ migrationای اجرا یا seedای را بازپخش نمی‌کند. تست‌های Idempotency فقط در دیتابیس موقت و ایزوله انجام می‌شوند. نقش اپلیکیشن فقط Viewهای داده تأییدشده را می‌خواند و به جداول خام دانش/منابع/بردارها دسترسی مستقیم ندارد.

برای متوقف کردن کانتینر، بدون حذف Volume:

```powershell
.\engineering\database-prep\scripts\Stop-Database.ps1
```

## Batch دوم داده منبع‌دار

Migration `0006_verified_unesco_destination_seed_batch2` هفت اثر دیگر را اضافه می‌کند: تخت سلیمان، چغازنبیل، مجموعه شیخ صفی‌الدین اردبیلی، مسجد جامع اصفهان، شهر سوخته، منظر فرهنگی میمند و هگمتانه. برای هر اثر صفحه توصیف و نقطه مرجع نقشه یونسکو، یک سند فارسی و دو Chunk ثبت می‌شود. دو منبع رسمی تکمیلی نیز برای موقعیت اداری شهر سوخته و میمند افزوده شده‌اند.

تمام این رکوردها `needs_review` می‌مانند. مختصات، نقطه مرجع ملک میراثی هستند و نباید به عنوان ورودی بازدیدکننده یا مسیر دسترسی تفسیر شوند. ۱۳ اثر باقی‌مانده از فهرست ۳۰ اثر ایران هنوز وارد نشده‌اند؛ برخی چندجزئی یا گسترده‌اند و قبل از ورود به مدل‌سازی دقیق‌تری نیاز دارند.

## سیاست ایمنی داده

- ۱۵ مقصد فعلی پروژه همچنان `needs_review` و `pending` هستند. مختصات آن‌ها خالی و `coordinate_role=unknown` باقی می‌ماند.
- ۱۷ رکورد UNESCO منبع و نقطه مرجع رسمی دارند و `verification_status=verified` هستند، اما عمداً `status=needs_review` دارند؛ بنابراین تا بازبینی و تأیید محصول در Viewهای Production و RAG منتشر نمی‌شوند. مختصات آن‌ها `property_reference` است، نه ورودی بازدیدکننده.
- ۱۲ مقصد QA دارای `coordinate_role=test_fixture` هستند.
- ۱۲ مقصد QA دارای `record_origin='synthetic_fixture'`، `is_synthetic=true` و `status='test_only'` هستند. مختصات آن‌ها ساختگی و صرفاً برای آزمون PostGIS هستند.
- اسناد و Chunkهای QA نیز با `test_only` و `is_synthetic=true` مشخص‌اند.
- کاربر، مکالمه، سفر، پیشنهاد، امتیازها، برنامه سفر و بازخورد نمونه همگی `is_synthetic=true` هستند.
- لینک‌های نمونه از دامنه رزروشده `.invalid` استفاده می‌کنند و غیرفعال‌اند.
- هیچ Embedding واقعی یا تماس Remote LLM تولید نمی‌شود.
- Viewهای مخصوص Production فقط داده‌های فعال و تأییدشده با منشأ معتبر را نمایش می‌دهند؛ مسیر اسناد، Chunkها و Embeddingها نیز به همان Viewهای کنترل‌شده محدود است. در دیتابیس تازه همه این Viewها عمداً خالی هستند؛ هر ۱۷ رکورد UNESCO نیز تا تأیید محصول منتشر نمی‌شوند.

**مهم:** این نسخه علاوه بر ۱۵ رکورد قدیمی تأییدنشده و ۱۲ مقصد مصنوعی QA، شامل دو Batch مجموعاً ۱۷ اثر میراث جهانی ایران با ارجاع رسمی به یونسکو، مختصات مرجع، ۱۷ سند فارسی و ۳۴ Chunk غیرمصنوعی است. این ۱۷ رکورد از نظر منشأ منبع بررسی شده‌اند، اما همگی `needs_review` باقی می‌مانند و تا تأیید صریح محصول وارد Viewهای Production/RAG نمی‌شوند. این مجموعه، پوشش کامل مقاصد ایران یا آمادگی پایلوت نیست؛ پس از عبور از تست‌های دیتابیس، می‌توانیم Batchهای واقعی بیشتری را با همین کنترل‌های منبع/مکان/مجوز/بازبینی اضافه کنیم. این دیتابیس صرفاً Development و Test است و هیچ داده مصنوعی نباید به Production منتقل شود.

## نتیجه و محدودیت فعلی

Validator آفلاین Python برای ۱۲ سند/۲۴ Chunk مصنوعی و ۱۷ سند/۳۴ Chunk منبع‌دار با موفقیت اجرا و Hashها و شمارش کاراکترها را تأیید کرده است. سپس روی دیتابیس Windows/Docker Desktop، بررسی Checksumها و تکرارپذیری Seedها و تمام تست‌های SQL شماره 000 تا 008 موفق شدند. گزارش نهایی برای تمام ۳۰ جدول، تعداد واقعی و مورد انتظار یکسان نشان داد و جمع کل ۴۱۹ از ۴۱۹ بود. خروجی نهایی Runner: `ALL DATABASE PRE-CODEX CHECKS PASSED`.

Migration 0006 روی دیتابیس مشترک موجود اعمال شده است؛ Migration 0007 هنوز روی آن اعمال نشده و استفاده از opt-in آن نیازمند تأیید جداگانه است. برای ادامه توسعه نیازی به Reset، حذف Volume یا اجرای مجدد Initialize نیست. این بسته همچنان Development/Test است و رکوردهای UNESCO و Shiraz تا بازبینی تحریریه `needs_review` می‌مانند؛ Viewهای Production مقصد و Retrieval خالی هستند. تست pgvector قرارداد ذخیره و nearest-neighbor را با بردارهای مصنوعی در تراکنش Rollbackشونده بررسی می‌کند و کیفیت معنایی یا Recall واقعی RAG را اثبات نمی‌کند.
