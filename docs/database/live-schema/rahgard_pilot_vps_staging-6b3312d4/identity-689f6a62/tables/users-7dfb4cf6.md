# identity.users

- **دیتابیس:** `rahgard_pilot_vps_staging`
- **نوع شیء:** جدول معمولی
- **شرح:** نیازمند توضیح دامنه‌ای تأییدشده از کد و مالک محصول
- **دسترسی خواندن:** از RLS/GRANT واقعی و مسیر API تطبیق شود؛ این مستند مقدار ردیفی نمی‌خواند.
- **دسترسی نوشتن:** از RLS/GRANT واقعی و مسیر API تطبیق شود؛ دسترسی مستقیم SQL به کاربر ندهید.
- **نمایش عمومی:** نامشخص تا تطبیق با View انتشار و API؛ پیش‌فرض خصوصی.
- **API مدل/مسیر:** مسیر مشخصی در کد پیدا نشده؛ نیازمند بررسی مالک ماژول.
- **فیلد فرم UI:** فرم مشخصی در فهرست نگاشت پیدا نشده؛ نیازمند بررسی UI.
- **منبع:** PostgreSQL `pg_catalog`، تراکنش فقط‌خواندنی، استخراج‌شده در `2026-11-24T06:58:13Z`
- **امنیت ردیفی (RLS):** خاموش؛ Forced=خیر
- **هشدار:** هیچ دادهٔ ردیفی، رمز، کوکی یا مقدار شخصی در این فایل استخراج نشده است.

## محدودیت‌ها و ارتباط‌ها

- **users_account_status_check** (`c`): `CHECK ((account_status = ANY (ARRAY['active'::text, 'disabled'::text, 'pending_deletion'::text, 'deleted'::text])))`
- **users_check** (`c`): `CHECK (((email IS NOT NULL) OR (phone_e164 IS NOT NULL) OR (auth_subject IS NOT NULL)))`
- **users_pkey** (`p`): `PRIMARY KEY (user_id)`
- **users_auth_subject_key** (`u`): `UNIQUE (auth_subject)`

## ایندکس‌ها

- `idx_users_status_created`: `CREATE INDEX idx_users_status_created ON identity.users USING btree (account_status, created_at DESC)`
- `uq_users_email_ci`: `CREATE UNIQUE INDEX uq_users_email_ci ON identity.users USING btree (lower(email)) WHERE (email IS NOT NULL)`
- `users_auth_subject_key`: `CREATE UNIQUE INDEX users_auth_subject_key ON identity.users USING btree (auth_subject)`
- `users_pkey`: `CREATE UNIQUE INDEX users_pkey ON identity.users USING btree (user_id)`

## سیاست‌های RLS

- سیاستی در `pg_policy` ثبت نشده یا برای این شیء صدق نمی‌کند.

## تریگرهای غیرسیستمی

- `trg_revoke_disabled_user_sessions`: `CREATE TRIGGER trg_revoke_disabled_user_sessions AFTER UPDATE OF account_status ON identity.users FOR EACH ROW EXECUTE FUNCTION identity.revoke_disabled_user_sessions()`

## نیازمندی تکمیل دامنه

- تعداد ستون‌های فاقد شرح صریح: **10** از **10**.
- مالک دامنه و توسعه‌دهنده باید تعریف تجاری، مقادیر مجاز، واحد پول/اندازه، مثال غیرواقعی، قواعد اعتبارسنجی و سطح دسترسی هر فیلد را از کد و API تأیید کنند.
- ستون‌ها را با فرم عمومیِ ویرایش SQL در اختیار کاربر قرار ندهید. فرم‌ها باید براساس نقش/قرارداد API باشند.
